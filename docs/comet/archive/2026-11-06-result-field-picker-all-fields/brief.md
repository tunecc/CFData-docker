# 目标

修复 Web 控制台「结果操作 → 字段与顺序」中的字段选择：当前它只列出“当前结果行里真的有值”的字段，一旦前端没有结果行（例如刷新页面、程序重启后尚未运行任务，或历史记录只恢复统计），可用字段就只剩 `IP:PORT`，用户无法预先勾选 `数据中心`、`落地区域`、`延迟` 等导出列。修复后字段选择恢复为固定、可预期的完整字段清单。

# 范围

## 目录结构

### 修改

- `combined_refactor/web/app.js`：`renderResultFieldOptions` 的可用字段来源不再依赖当前结果行；「全部选」「全选」与相关快速按钮改为基于固定字段清单；保持现有默认勾选（TXT 默认 `IP:PORT`、`数据中心`、`落地区域`）与自定义字段逻辑不变。
- `combined_refactor/web/test/`：补充字段清单与默认选择的 Node 单元测试（若现有测试结构可覆盖）。

### 不修改

- 不改动导出内容生成（`buildResultContent`）、TXT/CSV/订阅格式、分隔符、IPv6 方括号、起始/结束行与筛选语义。
- 不改动复制弹窗（`renderCopyFieldOptions`）的既有行为。
- 不改动任务结果的数据来源、WebSocket 恢复协议与历史记录结构。

## 现状事实

- `combined_refactor/web/app.js:3531`：`renderResultFieldOptions()` 用 `RESULT_FIELDS.filter((f) => f.key === 'ipport' || rows.some((r) => String(r[f.key] ?? '').trim() !== ''))` 生成字段清单，`rows` 来自 `getCurrentResultRows(resultModalMode)`。结果行为空时只剩 `ipport`。
- `combined_refactor/web/app.js:4197`：`getCurrentResultRows()` 在官方模式下读取页面内的 `scanData` / `testData`，它们只由 WebSocket 实时消息或 `task_restore_*` 回放填充；程序重启后回放缓冲为空。
- `combined_refactor/history.go:20-37`：历史记录只保存统计摘要与 Top 结果，不保存全量结果行，因此历史恢复（`history_analysis`）不会填充字段选择所依赖的结果行。
- `combined_refactor/web/app.js:3498-3505`：`getAllResultFieldOrder()`（「全部选」使用）同样按结果行过滤，无结果行时只能得到 `ipport`。
- 该按数据过滤的逻辑自 `5b2df78`（2026-04-28）引入字段选择器时就存在，不是最近某次提交新引入的回归；最近的后台任务与历史恢复改造让“前端没有结果行”更常见，问题因此更容易暴露。

# 非目标

- 不恢复“刷新或重启后仍能导出上一轮全量结果”的能力；历史记录保持统计摘要定位，不新增落盘全量结果。
- 不改变结果面板的数据来源下拉（扫描 / 详细测试 / 非标）语义。
- 不新增字段、不改字段标签、不改变 `IP:PORT` 恒选语义。
- 不改变 R2 别名模板、自动上传与 GitHub 上传链路。

# 验收示例

- A1：在前端没有任何结果行时（刷新页面或重启程序后未运行任务）打开「结果操作」面板，字段选择列出全部内置字段（26 个，含 `IP地址`、`端口号`、`延迟`、`数据中心`、`落地区域` 等）与已定义的自定义字段，不再只有 `IP:PORT`。
- A2：在已有扫描结果时打开面板，字段选择列出与无结果行时相同的完整字段清单；默认勾选仍为 `IP:PORT`、`数据中心`、`落地区域`（TXT），输出顺序列表与预览不受影响。
- A3：「全部选」在无结果行时选中全部字段，如齐全时按钮显示「全部选」；「仅 IP:PORT」把输出顺序收敛为 `IP:PORT`；「默认选择」恢复当前格式的默认勾选。
- A4：勾选当前结果中没有数据的字段后导出 TXT/CSV，对应列输出空值，拼接规则与现有导出一致；未勾选字段仍不出现。
- A5：`combined_refactor` 下 `go build ./...` 与 `go test ./...` 通过，前端 Node 测试通过，现有结果面板与导出测试不回归。

# 约束与不变量

- 字段清单固定来自 `RESULT_FIELDS` 定义，不在渲染时按运行时数据裁剪。
- 默认勾选与结果格式的耦合保持不变：`txt` 默认 `['ipport','dc','dcCountry']`（非标 `['ipport','dc','loc']`），`substore` 默认 `['ipport']`，`csv` 沿用现有紧凑字段顺序。
- 自定义字段仍按用户输入解析并追加到清单末尾；删除自定义字段时同步从输出顺序中移除。
- 结果面板设置持久化（`cfdata-result-panel` 的 `fieldOrder`）仍能恢复；已存顺序包含的字段必须仍在清单中。
- 不引入新的外部依赖。

# 决策

- D2（实现选择）：默认勾选、输出顺序与预览继续沿用现有格式相关默认值，不因字段清单变长而改变。
- D3（实现选择）：「全部选」在字段清单固定后选择全部字段；「仅 IP:PORT」「默认选择」保持现有语义。
