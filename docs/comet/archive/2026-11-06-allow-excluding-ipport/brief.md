# 目标

修复「结果操作」页的预览区域：当前没有结果行时只显示「暂无预览」，有结果时也只显示第一行、预览框只有一行高度，用户难以确认字段顺序与分隔符效果。改为——没有结果时用内置示例数据按当前设置生成 3 行预览并标注「示例」；有真实结果时显示前 5 行。`IP:PORT` 始终保留在输出中，本次不改变字段选择与导出规则。

# 范围

## 目录结构

### 修改

- `combined_refactor/web/app.js`：`buildResultPreview` 支持多行与示例数据；`updateResultPreview` 输出示例标识；`getSelectedResultRows` 的筛选/起止行语义保持不变。
- `combined_refactor/index.html`：预览容器补充示例标识元素（若无）与最小高度所需的类名/属性。
- `combined_refactor/web/styles.css`：预览框最小高度约 3 行，超过后可滚动。
- `combined_refactor/web/test/`：为预览行选择与示例生成抽出的纯函数补 Node 单测。

### 不修改

- 字段选择规则与 `IP:PORT` 始终保留的现状、默认勾选、字段清单。
- 导出内容生成（TXT/CSV/Sub-Store）与文件下载、R2/GitHub 上传。
- 结果面板设置的服务器持久化与本地缓存。

## 现状事实

- `combined_refactor/index.html:731`：预览容器为 `<pre class="result-preview" id="resultPreview">暂无预览</pre>`。
- `combined_refactor/web/app.js:4503-4519`：`buildResultPreview(format)` 通过 `getSelectedResultRows()` 取行；无行时返回「暂无预览」，有行时只取 `rows[0]` 生成一行。
- `combined_refactor/web/app.js:4521-4526`：`updateResultPreview()` 把结果写入预览并触发设置保存。
- 用户实例（`sha-56c8ae6`）实测：预览元素可见、无结果时显示「暂无预览」；注入两条模拟结果后输出 `162.159.147.210:443#HKG`，但只有 1 行、框高约 38px。
- 用户明确：`IP:PORT`（`162.159.147.210:443#...` 的前半段）必须始终保留，不修改字段规则；本次只修预览可见性。

# 非目标

- 不改变 TXT 的 `IP:PORT#字段` 拼接结构与 `#` 分隔语义。
- 不改变 CSV / Sub-Store 的输出结构。
- 不为历史记录或重启后的结果做持久化回放。
- 不改变预览区位置与整体面板布局。

# 验收示例

- A1：没有任何结果行时打开「结果操作」，预览区显示 3 行示例结果（使用当前字段顺序、分隔符与格式），并有「示例」标识，不再是「暂无预览」。
- A2：存在真实结果时预览显示前 5 行（受当前数据来源、筛选与起止行影响），按 TXT 规则每行含 `IP:PORT#字段`；超过 5 行时预览框可滚动。
- A3：切换字段勾选、输出顺序、分隔符或 IPv6 方括号后，示例/真实预览立即按新设置重新生成。
- A4：CSV 预览显示表头 + 前 5 行，Sub-Store 预览显示前 5 条目标，与导出规则一致。
- A5：`go build ./...`、`go test ./...` 与前端 Node 测试通过，导出与持久化测试不回归。

# 约束与不变量

- 有真实结果时不得再用示例数据；示例只在无可用结果行时出现。
- 示例数据必须明显可辨（「示例」标识 + 文档保留地址 192.0.2.x），不与真实结果混淆。
- 预览内容与导出内容使用同一套字段顺序、分隔符与格式规则，避免预览与导出不一致。
- 预览最多 5 行，不因结果规模卡顿；渲染不得触发额外网络请求。
- `IP:PORT` 的强制保留、字段选择持久化与服务器设置优先级保持不变。
