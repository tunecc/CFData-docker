# 官方批量测速速率限制处理

## Purpose

官方批量测速遇到测速源返回 HTTP 429 时，不再因连续几个 429 就直接中止整批；通过短退避重试与自动切换可用测速源，尽可能完成测速并让用户知道发生了什么。

## Requirements

### Requirement: 429 退避重试

单个 IP 的测速请求返回 429 时，系统 SHALL 等待后重试：首次等待 3 秒，第二次等待 6 秒，单个 IP 最多重试 2 次。重试成功 MUST 正常记录速度并继续原有达标判定。

重试等待 MUST 响应任务取消；取消时立即结束，不继续等待。

非 429 的失败（超时、连接错误、5xx 等）MUST 维持现有处理，不触发退避重试。

### Requirement: 自动切换测速源

重试后仍为 429 时，系统 SHALL 从内置测速源中选择另一个可用源（优先使用 `isSpeedURLAvailable` 标记可用的源），并从下一个 IP 开始使用新源继续测速。

切换 MUST 在日志中给出明确提示，且 MUST NOT 修改用户在配置中选择的测速源；换源只作用于本次批量测速。

### Requirement: 终止条件与提示

仅当换源后仍连续 6 个 IP 全部为 429 时，系统才终止批量测速。终止时 MUST 输出包含「已尝试更换测速源」的说明，并保持达标数量与总达标统计准确。

正常完成时 MUST 继续输出原有完成日志与 `official_speed_complete` 消息；已测结果 MUST NOT 丢失，`rateLimited` 字段 MUST 反映本次是否因限流终止。
