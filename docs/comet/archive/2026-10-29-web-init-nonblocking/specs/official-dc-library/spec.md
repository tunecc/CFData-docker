# 官方扫描数据中心库

## Purpose

为官方扫描提供可持久化的数据中心库：用户手动触发一次库扫描，系统把成功 IP 与其实际 `colo` 保存到容器 `/data`；页面按库中数据中心选择只扫描某个地区，并在库为空时提示先扫描。库只保存在本机，重启或重建容器后保留，不依赖任何第三方按地区划分的 IP 数据源。

## Requirements

### Requirement: 数据中心库扫描与持久化

Web 页面 SHALL 提供「更新数据中心库」入口。触发后系统 MUST 使用当前 IP 类型、端口、线程数、合格延迟与扫描方式扫描官方候选池，记录每个成功 IP 的 `colo` 与观测时间，并在扫描成功后把该 IP 类型的库保存为 `/data/dc-library-v4.json` 或 `/data/dc-library-v6.json`。

库扫描 MUST NOT 设置目标数据中心、MUST NOT 启用早停；扫描进度、日志与停止按钮 SHALL 复用现有任务机制。库扫描与官方扫描共用任务互斥，扫描期间 MUST NOT 同时启动其他官方任务；库扫描结果 MUST NOT 进入官方扫描结果表。

文件写入 MUST 原子化（临时文件 + rename）。文件 MUST 带明确 schema 版本并按 IP 类型分开保存。损坏或无法读取时系统 MUST 按空库处理并记录日志，不得阻止程序启动。

### Requirement: 库状态与数据中心选项

页面 SHALL 从库摘要渲染「数据中心」下拉：包含「全部」、库中每个 `colo` 以及「手动输入其他代码」。每个数据中心选项 MUST 显示城市/国家与库中 IP 数量；城市/国家只来自 `locations.json` 的展示映射，选择粒度 MUST 是单个 `colo`。

页面 SHALL 显示库更新时间、数据中心数与 IP 总数。初始化时库摘要 MUST 随 `init_config` 下发，或由页面通过状态查询获取，二者均 MUST 只读取本地数据、不触发网络探测。

### Requirement: 按数据中心扫描使用库内候选

当用户在「数据中心」下拉选择库中某个数据中心并启动官方扫描时，系统 MUST 只使用库中该数据中心的 IP 作为候选。系统 MUST NOT 自动回退到全量候选池；结果为空或不足时 SHALL 提示用户更新数据中心库。

每个候选 MUST 在扫描时重新请求 `speed.cloudflare.com/cdn-cgi/trace` 验证 `colo`，库内容 MUST NOT 被当作静态事实直接输出。目标 DC 过滤与早停语义 SHALL 与现有官方扫描一致。

### Requirement: 空库与手动更新

当前 IP 类型的库为空时，页面 MUST 禁用「数据中心」下拉并提示用户先扫描一次；「全部」全量扫描 MUST 保持可用，官方扫描开始按钮 MUST NOT 因空库被禁用。库扫描成功后下拉 MUST 自动启用并显示新数据。

库只由用户手动触发的库扫描更新；系统 MUST NOT 自动刷新库，也 MUST NOT 在普通官方扫描中自动写入库。库扫描成功完成后 MUST 整体替换该 IP 类型的库快照；取消或失败 MUST 保留旧库，不写入半成品。

### Requirement: 既有扫描路径与作用域

选择「全部」时官方扫描行为 MUST 与现状一致；选择「手动输入其他代码」时 MUST 继续使用全量候选池并应用目标 DC 过滤。NSB、详细测试、测速、导出、R2/GitHub 上传与自动调度流程 MUST 保持不变。

数据中心库本次只覆盖 Web 页面：CLI `-offdc`、自动调度 `offdc` 与相关配置字段 MUST 保持现状。库文件 MUST NOT 纳入 `reset_all_config` 的删除列表。

## 验收映射

本规格的验收项定义在 `brief.md` 的「验收示例」中（A6–A11），分别对应库扫描与持久化、按数据中心渲染与扫描、空库提示、手动更新语义、库扫描任务复用、既有路径与作用域。
