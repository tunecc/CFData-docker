# R2 与 Sub-Store 别名去重

## Purpose

R2 与 Sub-Store 目标列表每行的地址本身已包含 `IP:PORT`，别名不应再重复地址。别名只由用户选择的非 `IP:PORT` 字段组成；只选 `IP:PORT` 时仅输出地址。

## Requirements

### Requirement: 别名模板不含 IP:PORT

生成 R2 / Sub-Store 别名时，`IP:PORT` MUST NOT 参与别名；别名只使用其余已选字段对应的占位符，并保持用户设定的输出顺序与分隔符。

字段顺序为 `IP:PORT, 数据中心`、分隔符为 `-` 时，每行 MUST 输出 `<IP:PORT>#HKG` 形式，不得出现重复的 `<IP:PORT>-` 别名。

### Requirement: 仅选地址时的输出

用户只选择 `IP:PORT`、没有其他可用于别名的字段时，每行 MUST 只输出 `IP:PORT`，不带 `#` 与别名。

前端 MUST 用显式的“无别名”标记表达该状态，使服务端能与“旧配置未设置别名模板”区分；后者 MUST 继续回退到默认别名（数据中心-城市等），避免升级后悄悄丢失别名。

### Requirement: 兼容旧配置

服务端读取或保存别名模板时 MUST 净化已存在的 `{ipport}` 占位符：移除占位符并清理因此产生的首尾、连续分隔符，不得产生 `-HKG`、`HKG-` 或 `HKG--HK`。

净化 MUST 保留其余占位符与字面量，别名长度上限（200 字符）与禁止 `#` 的校验保持不变。旧配置 `{ipport}-{dc}` 升级后 MUST 直接按 `{dc}` 生效，无需用户手动重新保存；旧配置只有 `{ipport}` 时净化结果为空，MUST 按“无别名”处理（只输出地址），与用户重新保存后的行为一致。

### Requirement: R2 上传路径一致

R2 自动上传（自动调度 / CLI 管线）与 Web 手动上传 MUST 使用同一别名规则与同一净化后的模板，输出一致。

「Sub-Store 目标列表」导出（Web 与 CLI）MUST 保持现有默认别名规则（数据中心-城市等），本次不改为字段选择驱动。TXT/CSV 导出、结果预览与字段选择规则 MUST 保持不变。
