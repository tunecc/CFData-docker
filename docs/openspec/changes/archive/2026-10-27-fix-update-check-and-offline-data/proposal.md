# 修复更新检测与国内网络下的数据源失败

## 问题描述

1. 程序启动和 Web 页面版本检查会请求上游仓库 `PoemMisty/CFData-WEB` 的最新 Release。我们的构建版本是 `edge-c43b159`，上游最新为 `v1.8.5`，`versionIsOlder` 将 `edge` 解析为 0，因此每次启动都提示“发现新版本 v1.8.5”。
2. 在国内直连环境访问 `www.baipiao.eu.org` 会超时。首次运行且本地无缓存时：
   - `locations.json` 下载失败，城市/地区列为空；
   - `ips-v4`/`ips-v6` 下载失败，官方模式直接报错退出；
   - 精简 IPv4 功能同样无法读取地址库。

## 根因

- 更新检测的 API 地址固定为上游仓库的 `releases/latest`，展示链接也固定为上游仓库；版本比较没有排除 `edge-*`/`dev` 构建。
- 数据文件只在本地缺失时尝试远程下载，没有失败兜底；下载失败即视为不可用。

## 修复目标

- 更新检测改为 `tunecc/CFData-docker`：优先读取 Release，没有 Release 时读取最高的稳定 `v*` 标签；`edge-*`/`dev` 构建跳过比较；仓库无版本或网络失败时静默处理，仅在调试日志记录。
- 在二进制中内嵌 `locations.json`、`ips-v4.txt`、`ips-v6.txt` 快照。读取顺序为：本地缓存 → 远程下载 → 内置快照；内置快照不写入 `/data`，下次启动仍会尝试远程更新。
- 保持扫描、筛选、测速和镜像发布行为不变；不修改 `.github/`。

## 范围之外

- 不新增数据源配置项，不替换 baipiao 的远程地址。
- 不修改上游代码的其他更新检查、ASN 数据库或测速地址逻辑。
